# 要件ドキュメント: Java ASTパーサー

## 導入

この機能は、Javaのソースコードから抽象構文木（AST）を構築し、クラス、インターフェース、フィールド、メソッドなどの情報を抽出するためのパーサーを提供します。これにより、既存のJavaコードからクラス図を自動的に生成することが可能になります。

## 製品ビジョンとの整合性

product.mdに掲げられている「マルチプラットフォーム・マルチ言語」の目標をサポートします。Javaはオブジェクト指向プログラミングの代表的な言語であり、クラス図との親和性が非常に高く、この機能は多くのJava開発者に価値を提供します。

## 要件

### 要件1: Javaクラス・インターフェース情報の抽出

**ユーザーストーリー:** Java開発者として、パッケージ構造やクラスの階層を把握したいので、クラス名、インターフェース名、パッケージ名、継承・実装関係が抽出される機能が必要です。

#### 承認基準

1. WHEN Javaソースコードを解析する THEN システムは `class`, `interface`, `enum`, `record` を検出し、その名称とパッケージ名を取得しなければならない
2. WHEN クラスが他のクラスを継承（extends）、またはインターフェースを実装（implements）している THEN システムはそれらの名称を抽出しなければならない
3. WHEN アクセス修飾子（public, protected, private, package-private）が指定されている THEN システムはそれらを正しく認識しなければならない

### 要件2: フィールドとメソッドの抽出

**ユーザーストーリー:** クラス内部の詳細な定義を確認したいので、メンバ変数（フィールド）とメソッド（操作）の情報が抽出される機能が必要です。

#### 承認基準

1. WHEN クラス内のフィールドを解析する THEN システムは型名と変数名を抽出しなければならない
2. WHEN クラス内のメソッドを解析する THEN システムはメソッド名、戻り値の型、引数のリスト（名称と型）を抽出しなければならない
3. IF メンバが `static`, `final`, `abstract`, `native` として定義されている THEN システムはそれらの修飾子を抽出しなければならない

## 非機能要件

### コードアーキテクチャとモジュール性
- **単一責任原則**: `JavaAstParser` クラスはJavaの解析のみを担当します
- **モジュール設計**: 解析ロジックは他の言語のパーサーと共通の `IAstParser` インターフェースを実装します
- **依存管理**: Javaの解析には Tree-sitter または JavaParser の利用を検討します
- **明確なインターフェース**: 返却されるデータ構造は `ClassInfo` モデルに基づきます

### パフォーマンス
- 多数のクラスが含まれるファイルでも、ストレスなく解析が行える速度を維持すること

### セキュリティ
- 依存する解析ライブラリに起因するセキュリティリスクがないことを確認すること

### 可信性
- アノテーションやジェネリクスを多用する高度なJavaコードでも、正しく基本情報を抽出できること

### 可用性
- VS Codeがサポートする標準的なJava言語識別子（java）に対して有効であること
