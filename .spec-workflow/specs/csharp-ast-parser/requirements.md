# 要件ドキュメント: C# ASTパーサー

## 導入

この機能は、C#のソースコードから抽象構文木（AST）を構築し、クラス、インターフェース、プロパティ、メソッドなどの情報を抽出するためのパーサーを提供します。これにより、既存のC#コードからクラス図を自動的に生成することが可能になります。

## 製品ビジョンとの整合性

product.mdに掲げられている「マルチプラットフォーム・マルチ言語」の目標をサポートします。C#はエンタープライズ開発などで広く利用されており、これに対応することで、より多くの開発者が設計情報を容易に視覚化・管理できるようになります。

## 要件

### 要件1: C#クラス・インターフェース情報の抽出

**ユーザーストーリー:** C#開発者として、既存の構造を視覚化したいので、クラス名、インターフェース名、名前空間、継承・実装関係が抽出される機能が必要です。

#### 承認基準

1. WHEN C#ソースコードを解析する THEN システムは `class`, `interface`, `record`, `struct` を検出し、その名称と名前空間を取得しなければならない
2. WHEN クラスが他のクラスを継承、またはインターフェースを実装している THEN システムはそれらの名称を抽出しなければならない
3. WHEN アクセス修飾子（public, internal, protected, private）が指定されている THEN システムはそれらを正しく認識しなければならない

### 要件2: プロパティとメソッドの抽出

**ユーザーストーリー:** クラスの詳細な責務を把握したいので、プロパティ（属性）とメソッド（操作）の情報が抽出される機能が必要です。

#### 承認基準

1. WHEN クラス内のプロパティを解析する THEN システムは型名とプロパティ名を抽出しなければならない
2. WHEN クラス内のメソッドを解析する THEN システムはメソッド名、戻り値の型、引数のリスト（名称と型）を抽出しなければならない
3. IF メンバが `static`, `abstract`, `virtual`, `override` として定義されている THEN システムはそれらの修飾子を抽出しなければならない

## 非機能要件

### コードアーキテクチャとモジュール性
- **単一責任原則**: `CsharpAstParser` クラスはC#の解析のみを担当します
- **モジュール設計**: 解析ロジックは他の言語のパーサーと共通のインターフェース `IAstParser` を通じて利用されます
- **依存管理**: .NETの解析には標準的な Microsoft.CodeAnalysis (Roslyn) または Tree-sitter の利用を検討します
- **明確なインターフェース**: 返却されるデータ構造は `ClassInfo` に準拠します

### パフォーマンス
- 複雑なソースファイルや大規模なプロジェクトでも、ユーザーを待たせない速度で解析を完了すること

### セキュリティ
- 外部ライブラリを使用する場合、脆弱性のない安定したバージョンを選択すること

### 可信性
- 部分的なコード（コンパイルエラーがある状態）でも、可能な限りの情報を抽出できること

### 可用性
- VS Codeがサポートする標準的なC#言語識別子（csharp）に対して有効であること
