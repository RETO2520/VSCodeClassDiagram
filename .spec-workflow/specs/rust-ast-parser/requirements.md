# 要件ドキュメント: Rust ASTパーサー

## 導入

この機能は、Rustのソースコードから抽象構文木（AST）を構築し、構造体（struct）、トレイト（trait）、列挙型（enum）、およびそれらに定義された関数（impl）などの情報を抽出するためのパーサーを提供します。これにより、Rustコードからクラス図相当の視覚化情報を自動生成できます。

## 製品ビジョンとの整合性

product.mdに掲げられている「マルチプラットフォーム・マルチ言語」の目標をサポートします。Rustは高い安全性を持ち、近年急速に普及している言語です。Rust特有の構造（TraitやImpl）をクラス図の概念にマッピングすることで、Rust開発者の設計作業を支援します。

## 要件

### 要件1: Rust構造体・トレイト情報の抽出

**ユーザーストーリー:** Rust開発者として、プログラムのデータ構造とインターフェースを把握したいので、構造体名、トレイト名、およびそれらの関連（実装関係）が抽出される機能が必要です。

#### 承認基準

1. WHEN Rustソースコードを解析する THEN システムは `struct`, `trait`, `enum` を検出し、その名称を取得しなければならない
2. WHEN `impl Trait for Struct` のような実装ブロックが存在する場合 THEN システムは構造体とトレイトの関連を抽出しなければならない
3. WHEN 可視性（pub, pub(crate)等）が指定されている THEN システムはそれらを正しく（public/private等にマッピングして）認識しなければならない

### 要件2: メンバとメソッドの抽出

**ユーザーストーリー:** 構造体の詳細や提供されている機能を把握したいので、フィールドと関連関数（メソッド）の情報が抽出される機能が必要です。

#### 承認基準

1. WHEN 構造体内のフィールドを解析する THEN システムは型名とフィールド名を抽出しなければならない
2. WHEN `impl` ブロック内の関数を解析する THEN システムは関数名、戻り値の型、引数のリスト（名称と型）を抽出しなければならない
3. IF 関数が `&self`（インスタンスメソッド）を持つか、あるいは関連関数（スタティックメソッド相当）であるかを識別しなければならない

## 非機能要件

### コードアーキテクチャとモジュール性
- **単一責任原則**: `RustAstParser` クラスはRustの解析のみを担当します
- **モジュール設計**: 解析ロジックは `IAstParser` インターフェースに従い、他の言語パーサーと一貫性を保ちます
- **依存管理**: Rustの解析には Tree-sitter (tree-sitter-rust) の利用を強く推奨します
- **明確なインターフェース**: `ClassInfo` モデルにRustの概念を適切にマッピングして情報を返却します

### パフォーマンス
- Rustのマクロ展開など複雑な要素があっても、タイムアウトせずに解析が完了すること

### セキュリティ
- 解析処理中にメモリ安全性が保たれる手法を選択すること

### 可信性
- `mod` によるファイル分割が行われている場合でも、単一ファイル内の情報を正確に抽出できること

### 可用性
- VS Codeがサポートする標準的なRust言語識別子（rust）に対して有効であること
